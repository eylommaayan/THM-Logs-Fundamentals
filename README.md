Task 1: מבוא ללוגים (Introduction to Logs)
תוקפים מנסים להיות חכמים ולהסתיר עקבות, אבל בדיוק כמו שבלשים בשטח מוצאים טביעות רגליים בשלג או תיעוד במצלמות אבטחה, בעולם הדיגיטלי יש לנו לוגים (Logs).

לוגים הם "טביעות האצבע הדיגיטליות" שמותירה כל פעילות במערכת – בין אם היא תקינה ובין אם היא זדונית.

שימושים מרכזיים בלוגים:
Security Monitoring: זיהוי התנהגות חריגה בזמן אמת.

Incident Investigation (חקירת אירועים): הבנת שורש הבעיה (Root Cause Analysis) ומה בדיוק קרה בזמן התקיפה.

Troubleshooting: אבחון שגיאות טכניות במערכת או באפליקציה.

Auditing and Compliance: עמידה בתקני רגולציה ותיעוד פעולות לצרכי בקרה.

## Task 2: סוגי לוגים (Types of Logs)

כדי לייעל את החקירה, הלוגים מחולקים לפי סוג המידע שהם מספקים. במקום לחפש בכל המערכת, אנחנו ניגשים ישר ל"תיקייה" הרלוונטית:

| סוג לוג | שימוש עיקרי | דוגמאות |
| --- | --- | --- |
| **System Logs** | פתרון תקלות במערכת ההפעלה. | עליית המערכת, טעינת דרייברים, שגיאות חומרה. |
| **Security Logs** | זיהוי וחקירת אירועי אבטחה. | **התחברות (Authentication)**, שינוי הרשאות, שינוי מדיניות אבטחה. |
| **Application Logs** | אירועים שקשורים לאפליקציה ספציפית. | שגיאות בתוכנה, עדכוני אפליקציה, אינטראקציית משתמש. |
| **Audit Logs** | מעקב אחר שינויים במערכת (לצרכי תאימות/Compliance). | גישה לקבצים רגישים, שינוי הגדרות מערכת ע"י משנה. |
| **Network Logs** | ניטור תעבורת רשת נכנסת ויוצאת. | חיבורי רשת, לוגים של **Firewall**. |
| **Access Logs** | תיעוד גישה למשאבים ספציפיים. | כניסות לשרת אתר (Web), גישה למסדי נתונים (DB). |

**Log Analysis (ניתוח לוגים):** זו הטכניקה של שליפת מידע בעל ערך מתוך ערימת הנתונים. מכיוון שאי אפשר לקרוא הכל בעיניים, משתמשים בכלים אוטומטיים או ידניים (כמו אלו שנלמד במשימות הבאות).

## תרגום וסיכום: ניתוח לוגים ב-Windows (Task 3)

בדומה למערכות הפעלה אחרות, Windows מתעדת פעילויות רבות המתרחשות בה. לוגים אלו מאוחסנים בקבצים מופרדים לפי קטגוריות:

### סוגי לוגים מרכזיים ב-Windows:

* **Application (אפליקציה):** מכיל מידע על תוכנות שרצות במערכת (שגיאות, אזהרות ובעיות תאימות).
* **System (מערכת):** מכיל מידע על פעולות של מערכת ההפעלה עצמה (דרייברים, חומרה, הפעלה וכיבוי).
* **Security (אבטחה):** **זהו הלוג החשוב ביותר לאבטחה.** הוא מתעד ניסיונות התחברות, שינויים בחשבונות משתמשים ושינויי מדיניות אבטחה.

### מזהי אירועים (Event IDs) שחובה להכיר:

מזהי אירועים הם מספרים ייחודיים לכל סוג פעולה. שימוש בהם מאפשר לסנן את הרעש ולמצוא בדיוק מה שחיפשנו:

| Event ID | תיאור הפעולה |
| --- | --- |
| **4624** | התחברות מוצלחת למערכת. |
| **4625** | ניסיון התחברות שנכשל. |
| **4720** | **נוצר חשבון משתמש חדש.** |
| **4722** | חשבון משתמש הופעל (Enabled). |
| **4724** | בוצע ניסיון לאיפוס סיסמה. |

### כלי העבודה: Event Viewer

בניגוד ללוגים אחרים שדורשים עורכי טקסט, ל-Windows יש כלי גרפי מובנה בשם **Event Viewer**. ניתן להשתמש באפשרות **Filter Current Log** כדי להציג רק את ה-Event ID שמעניין אותנו.

Task 3: ניתוח לוגים ב-Windows (Event Viewer)
במשימה זו חקרנו פעילות חשודה בשרת Windows תוך שימוש בכלי ה-Event Viewer. המפתח לפתרון היה שימוש בסינונים (Filters) לפי מזהי אירועים (Event IDs) ספציפיים בלוג ה-Security.

שלבי העבודה:
פתיחת ה-Event Viewer ומעבר ל-Windows Logs -> Security.

שימוש באופציית Filter Current Log בצד ימין לחיפוש אירועים ממוקדים.

ממצאי החקירה:
מהו שמו של חשבון המשתמש האחרון שנוצר במערכת?

איך מצאנו: ביצענו סינון ל-Event ID 4720 (יצירת משתמש). תחת הלשונית General, זיהינו את שם המשתמש החדש.

תשובה: CyberTeam

איזה חשבון משתמש יצר את החשבון הנ"ל?

איך מצאנו: באותו אירוע (4720), הסתכלנו תחת שדה ה-Subject שמתאר מי ביצע את הפעולה.

תשובה: Administrator

באיזה תאריך הופעל (Enabled) חשבון המשתמש הזה?

איך מצאנו: ביצענו סינון ל-Event ID 4722 (חשבון הופעל) וחיפשנו את התאריך והשעה (Logged).

תשובה: 11/15/2024

האם החשבון הזה עבר גם איפוס סיסמה?

איך מצאנו: ביצענו סינון ל-Event ID 4724 (ניסיון איפוס סיסמה). מאחר וקיבלנו תוצאה עבור המשתמש CyberTeam, התשובה חיובית.

תשובה: Yes

Task 4: ניתוח לוגים של שרת אינטרנט (Web Access Logs)
במשימה זו ניתחנו קובץ לוג של שרת Apache (access.log) באמצעות פקודות Linux בטרמינל.

פקודות מפתח לניתוח:
grep "GET /contact" access.log - למציאת כל בקשות ה-GET לדף צור קשר.

grep "172.16.0.1" access.log | grep "POST" - סינון כפול למציאת פעולות שליחת נתונים מ-IP ספציפי.

ממצאי החקירה:
ה-IP שביצע את בקשת ה-GET האחרונה לכתובת "/contact":

תשובה: 10.0.0.1

מתי בוצעה בקשת ה-POST האחרונה על ידי ה-IP ‏"172.16.0.1"?

איך מצאנו: השורה האחרונה בסינון הראתה את התאריך והשעה המדויקים.

תשובה: 06/Jun/2024:13:55:44

לאיזה URL בוצעה בקשת ה-POST הנ"ל?

תשובה: /contact

סיכום החדר
החדר סיפק הצצה לעולם הראיות הדיגיטליות. למדנו שלוגים הם "טביעות האצבע" של כל פעולה במערכת, ושהיכולת לסנן ולנתח אותם היא קריטית לזיהוי תקיפות בזמן אמת ושחזור אירועים (Forensics).
